## 1. 背景与目标

### 理想产品形态

- 玩家 **不用手填** 技能热键、不用写 CD 秒数。
- 程序自动读取 **整块技能栏**（不仅底下一排），识别：
  - 快捷键
  - 技能图标 → 技能身份（库匹配）
  - CD 状态（ready / cooling）
- UI 侧 **只读技能表** 实时刷新；玩家拖技能/改键后自动更新。
- 库命中且可挂机 → 可释放；未识别 / 无效 → **永不释放**。
- 普攻作主输出（无 CD）；技能在 ready 时夹带释放。

### 本任务技术目标

```
L1 定位 skill_bar
  → L2 多行切格
  → 图标 vs 静态技能库比对（模板 / 感知哈希 / ORB）
  → 输出 skill_id / name / hotkey / cd / castable
```

**P0 不为「认是哪个技能」单独训练分类大模型。**  
模型（现有 L1）只负责 **技能区域在哪**；身份靠 **图标库比对**。

### 非目标

- [ ] ~~读游戏内存~~（禁止）
- [ ] ~~替代 L1 布局模型全量重训~~（仅在 skill_bar 框不全时微调）
- [ ] ~~回血回蓝业务策略细节~~
- [ ] ~~对外分发扒取的图标包~~
- [ ] ~~P0 必做 CD 剩余秒数 OCR~~（ready/cooling 即可）

## 2. 可行性结论（已拍板）

| 问题 | 结论 |
|------|------|
| 扒资料站/官网静态图标复用？ | **可以**，作种子 + 元数据 |
| 运行时匹配用哪套图？ | **以游戏内校准图标 `icons_ingame` 为准** |
| 还要训技能识别模型吗？ | **P0 不需要** |
| 模型要做什么？ | 定位技能栏 + 切格 + CD 启发 |
| 比对算法？ | 感知哈希快筛 + NCC / ORB 精排 |
| 何时才考虑轻量 embedding？ | 校准后 Top1 仍 &lt;90% 或库规模爆炸 |

### 风险

1. 官网图 ≠ 游戏技能栏渲染（尺寸、描边、饱和度、CD 蒙层）。
2. 怀旧/版本换皮。
3. CD 中变灰 → 需去灰预处理或 ready 模板。
4. 扒站版权与 ToS：仅本地离线库。
5. 空槽/物品混栏 → 未命中 = 不释放。

## 6. 挂机时序（目标行为，供联调）

```
循环:
  选怪
  普攻(主输出，无 CD)
  若有 matched && hang_usable && ready → 夹 1 个技能（尊重公共 CD）
  否则继续普攻
  空血 → 立刻换怪
```

- 不再以「每个技能手写 30s/60s」为真相。
- `IntervalMs` 最多作视觉 Unknown 时保险丝。
