# 龙伴行目标模式

## 总目标

完成一个真实可用的“龙伴行”32 位稳定版客户端。

目标不是重写玩法，也不是自由发挥新逻辑，而是在新前端、新配置、新日志、新交互下，尽量复刻并迁移旧客户端已经可用的核心功能，同时移除旧登录授权链和旧命名。

第一阶段只聚焦一条主线：挂机、打怪、状态判断、回血回蓝、宠物技能、自动回点、死亡回点、卡点恢复、安全清包。

抢小、抢反、马贼、生活、帮贡、答题等功能先不进入当前目标模式，等这条主线真实可用后再排期。

7. 宠物出战
8. 宠物回血 / 宠粮逻辑
9. 自动回点
10. 死亡回点
11. 卡点恢复
12. 清包识别
13. 清包白名单 / 保留贵重物品 / 只生成候选，不默认出售
14. 游戏内置挂机开关识别与触发

## 运行边界

1. 只处理龙伴行项目、自有旧程序、自有授权数据、自有配置和本地采样资产。
2. 所有代码放在：`<REPO_ROOT>`。
3. 不修改原始旧程序和授权数据目录。
4. 不引入旧登录、旧授权 DLL、旧账号体系。
5. 不再使用旧软件名称暴露到前端。
6. 禁止内存写入、注入、Hook、补丁、封包修改、绕过第三方安全组件。
7. 允许做“只读运行态读取”研究，但必须满足：
   - 只读，不写入。
   - 不注入 DLL。
   - 不 Hook 游戏函数。
   - 不 patch 客户端。
   - 不绕过第三方安全组件。
   - 可关闭。
   - 有日志。
   - 有诊断证据。
   - 失败必须回退到截图 / 图色 / OCR / 外部按键逻辑。
8. 运行态数据来源优先级：
   - 截图 / 图色 / OCR。
   - 旧数据模板。
   - 用户采样资产。
   - 本地文件资产解析。
   - 只读运行态读取。
9. 只读内存能力先作为状态增强，不默认接管核心业务；必须经过诊断和验收后再逐项接入。

## 技术路线

继续使用：

- `.NET 8`
- `WPF`
- `x86`
- 服务层 + ViewModel + 前端展示分离

保持架构边界：

- UI 只做展示、输入、状态绑定。
- 业务逻辑只能写在服务和控制器。
- 打怪逻辑写在 `NormalHangController`。
- 回点逻辑独立服务化，但作为挂机能力组合使用。
- 清包逻辑独立服务化，默认只读分析。

- 日志统一走 `RuntimeLogService`。
- 配置统一走配置服务，修改后自动保存到当前方案。

## 只读运行态读取目标模式

新增统一运行快照接口：

```text
IRuntimeStateProvider
  |- ScreenshotOcrRuntimeStateProvider
  |- StaticAssetRuntimeStateProvider
  |- ReadOnlyRuntimeStateProvider
```

运行快照统一输出：

- 人物状态
  - 名称
  - 血量百分比
  - 蓝量百分比
  - 是否死亡
  - 门派 / 职业信息（如能可靠识别）
- 目标状态
  - 名称
  - 血量百分比
  - 是否玩家
  - 是否怪物
  - 是否可攻击
  - 是否丢失目标
- 宠物状态
  - 是否出战
  - 宠物血量百分比
  - 宠物技能状态（能可靠读取或识别时再接入）
- 场景状态
  - 地图名
  - 坐标 X/Y
  - 是否副本
  - 是否野外
- 背包状态
  - 背包是否打开
  - 格子占用
  - 物品候选信息

只读读取的使用原则：

1. 优先读取稳定、可验证、不频繁漂移的数据。
2. 所有读取结果必须带来源和置信度。
3. 只读读取失败时，不允许卡死业务。
4. 截图识别和只读读取冲突时，记录冲突日志，优先采用更可信来源。
5. 不允许把未验证的地址、偏移、结构硬编码到通用配置。
6. 32 位客户端使用独立配置，64 位客户端以后单独规划。
7. 每个版本的客户端必须记录版本号、路径、SHA256 和读取能力状态。

只读读取分三阶段：

### 阶段 A：只读进程证据

先完成：

- PID
- 窗口句柄
- 进程路径
- 进程位数
- 客户区尺寸
- 版本号
- SHA256
- 启动时间
- 探针状态

验收：

- `readonly-probe` 能生成 JSON 证据。
- 不发送按键。
- 不点击。
- 不读写游戏状态。
- 不影响游戏运行。

### 阶段 B：只读状态快照

再逐步研究：

- 人物血量 / 蓝量
- 目标血量
- 当前目标类型
- 地图名
- 坐标
- 死亡状态
- 背包状态

验收：

- 每个字段都必须能和截图 / OCR 结果交叉验证。
- 每个字段必须有“不可信 / 不可用 / 可用 / 稳定”状态。
- 不稳定字段不能进入自动化决策。

### 阶段 C：业务接入

只在验证稳定后接入：

- 打死换怪
- 玩家目标保护
- 回血回蓝
- 自动回点
- 死亡回点
- 清包候选

接入规则：

- 只读状态只做判断，不做写入。
- 动作仍走 `InputService` / 鼠标点击 / 游戏内置功能开关。
- 一旦读取异常，立即降级外部识别。

## 打怪目标模式

打怪循环必须按以下逻辑执行：

1. 没有目标时，按选怪键。
2. 读取目标状态，来源可以是截图 OCR、图色或只读运行态快照。
3. 判断目标是否可攻击。
4. 如果是玩家、宠物、不可攻击目标、灰名 / 黄名保护目标，则切换下一个目标。
5. 新目标确认可攻击后，普通攻击只触发一次。
6. 技能按独立计时器循环释放。
7. Buff 类技能 CD 到了就自动释放。
8. 目标血量归零或目标丢失后，重新选怪。
9. OCR / 图色 / 只读读取失败时不阻塞基础打怪，可以退化为“选怪 + 攻击”模式。
10. 玩家选择“打死换怪”时必须监控目标血条。
11. 玩家选择“抢怪模式”时可简化为快速选怪攻击，但仍必须做玩家保护。

## 玩家目标保护

默认开启。

识别依据优先级：

1. 目标面板是否有人物头像。
2. 目标面板左侧是否存在门派标识区域。
3. 目标血条下方是否存在玩家特征条。
4. 只读运行态是否能稳定标识目标类型。
5. 名字颜色 / 面板结构辅助判断。

不能只依赖蓝条和怒气条，因为玩家蓝量或怒气可能为空。

不能只依赖红色血条，因为怪物、BOSS、小头目也可能有红色血条。

只要判断为玩家，默认不攻击，立即切换目标，并写日志说明。

## 状态与药品逻辑

状态识别：

- 人物血量百分比
- 人物蓝量百分比
- 宠物血量百分比
- 目标血量百分比

状态来源：

- 优先截图 / 图色 / OCR。
- 可用时用只读运行态快照交叉验证。
- 冲突时写日志并按置信度选择。
- 不可信时不触发高风险动作。

动作逻辑：

- 吃药回血：低于阈值触发，药品公共 CD 默认 10 秒。
- 吃药回蓝：低于阈值触发，药品公共 CD 默认 10 秒。
- 血迹回蓝：低于蓝量阈值触发，宠物技能 CD 默认 30 秒。
- 共生回血：低于血量阈值触发，宠物技能 CD 默认 30 秒。
- 宠物回血：宠物血量低于阈值触发宠粮或配置动作。
- 宠物出战：默认出战当前宠物。

血迹 / 共生优先做鼠标点击宠物技能区域，不强依赖玩家把宠物技能拖进技能栏。

## 回点目标模式

回点分三类：

1. 挂机回点
2. 土灵回点
3. 死亡回点

必须完成：

- 坐标采集
- 地图识别
- 当前坐标识别
- 偏离距离判断
- 卡点判断
- 回点执行
- 回点后恢复挂机
- 死亡后复活 / 回城 / 回点流程

地图和坐标来源：

- 优先外部识别和用户采样。
- 可用时用只读运行态快照增强。
- 只读数据不稳定时，不能触发自动回点。

游戏内置挂机和外部按键打怪都要支持回点，但实现要分开：

- 外部按键打怪：由龙伴行控制选怪、技能、回点。
- 游戏内置挂机：龙伴行只负责开启内置挂机、监控坐标、异常回点、死亡处理。

## 清包目标模式

清包先做安全版本：

1. 只识别背包格子。
2. 只生成候选列表。
3. 默认不自动出售。
4. 必须有白名单。
5. 未识别物品默认保护。
6. 贵重物品默认保护。
7. 任务物品默认保护。
8. 绑定物品默认保护。
9. 出售动作必须二次确认，不能默认执行。

清包数据来源：

- 背包截图 / 图色识别
- 用户白名单 / 黑名单
- 旧数据清单
- 可用时使用只读运行态快照辅助判断格子和物品状态

后续再做：

- 随身商店
- 随身银行
- 自动出售
- 自动存放
- 清包后恢复挂机

## 识别与分辨率目标

第一稳定分辨率先以当前常用窗口为基准：

- 1920x1080
- 2560x1369
- 1024x768 作为兼容画像

必须支持分辨率画像：

- 每个分辨率有独立识别区域。
- 用户可采样校准。
- 识别区域必须能导出截图证据。
- 默认区域不准写死成唯一标准。
- 只读运行态读取不能替代截图校准，因为前端仍需要可视化证据。

## 当前执行顺序

第一阶段只做以下内容，不插入其他大功能：

1. 修正打怪循环。
2. 完成玩家目标保护。
3. 完成血蓝 / 宠物 / 目标识别区域校准。
4. 完成只读运行态快照接口和诊断，不默认接管业务。
5. 完成回血回蓝 / 血迹 / 共生 / 宠物回血冷却逻辑。
6. 完成打死换怪。
7. 完成野外内置挂机 / 副本外部打怪的模式选择。
8. 完成自动回点。
9. 完成死亡回点。
10. 完成清包只读识别和候选列表。
11. 每一步都必须有诊断命令、日志和截图 / JSON 证据。

## 验收标准

验收时必须看到：

1. 绑定 32 位游戏窗口成功。
2. 启动后能稳定打怪。
3. 不会攻击玩家目标。
4. 目标死亡后能换怪。
5. 技能释放节奏稳定。
6. 血量低能回血。
7. 蓝量低能回蓝。
8. 血迹 / 共生不会因 CD 卡死。
9. 宠物没血有处理逻辑。
10. 偏离挂机点能回点。
11. 死亡后能进入死亡回点流程。
12. 清包能识别背包并生成候选，不误卖。
13. 所有配置实时保存。
14. 所有关键动作有日志。
15. 所有识别区域能截图验证。
16. `readonly-probe` 能生成只读进程证据。
17. 只读运行态快照字段必须带来源、置信度和可用状态。
18. 只读读取失败时，业务能自动回退外部识别或基础按键逻辑。

## 执行要求

从现在开始，按这个目标模式执行。

不要再发散做抢小、抢反、马贼、生活、帮贡等二期功能。

先把挂机、回点、死亡、清包这条主线做到真实可用。

只读运行态读取可以做，但必须先诊断、后验证、再接入；任何不稳定字段都不能进入自动化决策。
