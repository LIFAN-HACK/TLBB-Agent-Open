# TLBB Agent 目标模式任务书

## 1. 项目目标

TLBB Agent 是龙伴行 的新一代整合客户端。目标不是修旧 UI，也不是 patch 历史执行文件，而是在不引入敏感链路的前提下，把历史版本 / 龙伴行授权数据里已经存在、可验证、可迁移的成熟逻辑，重新落到一个现代化、可维护、可诊断的 32 位稳定版 Windows 桌面软件中。

第一阶段交付标准：用户能看到并运行一个真实软件，能绑定 32 位 `Bin\Game.exe`，能配置、启动、暂停、停止主要模式，P0 功能真实驱动绑定窗口，不是假按钮、不空跑、不只做演示 UI。

## 2. 绝对边界

- 不引入 `敏感组件`。
- 不引入登录链路、注册、账号绑定、账号充值、账号改密、会员账号、会员密码、远端授权请求、授权失败弹窗、账号过期提示、启动强制登录拦截。
- 不修改 `本机授权数据目录` 原始文件。
- 不处理第三方游戏平台、第三方账号系统、安全组件、反作弊、验证码或风控。
- 历史执行文件 / DLL 只作为静态分析、运行态观察、释放数据、配置字段、字库、坐标和行为蓝本来源；最终在新项目服务层重写。

## 3. 迁移原则

旧模块没有源码时，不声称“代码直接搬过来”。迁移的是：

- 配置字段
- 字库模板
- OCR 识别词
- 图色模板
- 地图、坐标、路线
- NPC / 怪物 / BOSS 名称
- 流程参数
- 状态机思路
- 运行态可观察行为

每个功能必须记录来源模块、来源路径、数据类型、是否含授权字段、去授权说明、新项目目标格式、接入服务或状态机、验收方式。

## 4. 前端目标模式

TLBB Agent 是配置密集型工具软件，不采用卡片式概览菜单。

最终 UI：

- 左侧固定区：窗口绑定、头像截图、标题、PID、进程路径、32/64 位提示、当前配置方案、自动重连、自动上号、喊话、当前模式、启动/暂停/停止。
- 右侧横向一级 Tab：通用配置、挂机、活动、生活、任务自动化、数据调试。
- Tab 内部使用胶囊式 tag / 分段选择切换具体模式。
- 同一时间只能运行一个主模式。
- 底部全局日志：运行日志、错误日志、状态机日志、过滤、复制、导出。

首页不是概览，首页是通用配置：门派选择、技能预设、常用快捷键、目标选择预设、血蓝阈值、公共 CD。选择峨眉后自动启用加血能力，但联动逻辑必须写在服务层，不能写在 UI。

## 5. 后端架构

所有核心能力必须落在服务层：

- `AppInitService`
- `WindowBindingService`
- `WindowCaptureService`
- `TemplateOcrService`
- `InputService`
- `StateMachineEngine`
- `ProfileConfigService`
- `RuntimeLogService`
- `LegacyDataAdapter`

所有主功能必须是独立控制器或独立状态机：

- `NormalHangController`
- `ReturnPointController`
- `HorseBanditModeController`
- `NpcGrabController`
- `AutoRebelController`
- `AutoMonkController`
- `DungeonController`
- `TradeRunController`
- `GatheringController`
- `MiningController`
- `TreasureMapController`
- `TeacherTaskController`
- `GuildContributionController`
- `QuizController`

强制规则：

- UI 只负责展示、输入、命令和状态绑定。
- code-behind 不写业务逻辑。
- 按钮事件不直接写自动化逻辑。
- 配置只走 `ProfileConfigService`。
- 日志只走 `RuntimeLogService`。
- 输入只走 `InputService`。
- 截图只走 `WindowCaptureService`。
- OCR 只走 `TemplateOcrService`。
- 多个模式不能混成一个大循环。

## 6. P0 第一阶段必须真实可用

### P0-1 窗口绑定

来源：历史版本。

必须完成：拖拽准星绑定、句柄、PID、标题、进程路径、32/64 位判断、解绑、重新绑定、绑定后头像截图、64 位提示。

验收：可绑定 32 位 `Bin\Game.exe`；多开时能通过头像截图确认角色；异常有日志。

### P0-2 按键打怪

主来源：历史版本。补充来源：马系列技能配置、生活源A技能间隔字段。

必须完成：自动打怪、技能循环、打死换怪、峨眉加血、指定目标、目标策略、技能间隔、F1-F12、自定义快捷键、技能启用/禁用、公共 CD、状态日志。

验收：绑定窗口后能按配置发送技能键；技能间隔和公共 CD 生效；峨眉自动启用加血；日志可复查选怪、攻击、换怪、回血、等待 CD。

### P0-3 挂机返点

来源：历史版本 + 坐标源A 坐标数据。

必须完成：坐标录入、多坐标保存、地图绑定、定点打怪返点、土灵返点、死亡返点、卡点恢复、异常返回、按角色/窗口/方案保存。

验收：能导入坐标源A 坐标；能保存多组方案；日志显示当前坐标、目标返点、距离、失败原因和恢复动作。

### P0-4 马贼模式

主来源：历史版本。补充来源：坐标源A、跟随源A。

必须独立实现 `HorseBanditModeController`。

必须完成：自动跟随队长、队长/队员识别、组队跟随、识别马贼喽啰、识别夺宝马贼、抢小丹/天降奇兽能力迁移、打死后找下一只、丢失目标恢复、超出范围处理、坐骑状态处理、队伍异常处理、状态日志。

状态机：Idle、BindWindow、CheckClient32Bit、CheckTeamState、FollowLeader、SearchHorseBandit、SelectTarget、AttackTarget、WaitBattle、DetectKillOrLostTarget、Recover、ReturnToFollow、Stop。

验收：不混入普通挂机大循环；跟随、找马、选马、攻击、丢失恢复都有可见状态和日志；跟随源A双开参数能迁移为配置项。

### P0-5 抢 NPC

主来源：历史版本 抢抢页。

必须拆分 `NpcTargetingService`、`NpcActionService`、`NpcGrabController`。

必须完成：抢反、抢小、抢小丹、抢小2、抢和尚、抢箱子、抢上架、高甲卫、高甲卫23、目标启用/禁用、扫描间隔、点击间隔、失败重试、状态日志。

验收：可选择一个或多个抢 NPC 目标；扫描、选中、点击、失败重试都有日志；目标识别和动作执行分离。

### P0-6 自动反贼

主来源：历史版本。

必须完成：坐标录入、地图选择、保存设置、自动刷反、路线执行、队伍状态处理、目标识别、进战检测、战斗结束检测、异常恢复。

验收：独立 `AutoRebelController`；不和挂机、和尚、三环共用大循环；日志显示地图、坐标、目标状态、战斗状态、异常恢复。

### P0-7 自动和尚

主来源：历史版本。

必须完成：地图选择、坐标录入、自动刷和尚、活动结束前停止或退出、状态日志。

验收：独立 `AutoMonkController`；可保存和尚路线配置；运行状态与反贼分离。

### P0-8 自动三环 / 副本

主来源：历史版本 副本设置。

必须完成：老三环、新三环、输入次数、队伍编号、是否我去左桥、新三 2 boss 站位配置、执行脚本、结束清包、完成后衔接其他任务。

验收：独立 `DungeonController`；老三环/新三环配置分开；次数、队伍编号、站位、清包能保存；日志显示副本阶段。

## 7. P1 第二阶段覆盖功能

P1 用于覆盖其他龙伴行模块已有能力，不做无来源扩展。

- 跑商：来源跑商源A + 马系列跑商配置；完成路线、买点、卖点、NPC、地图、坐标、状态机、失败处理。
- 材料加工：来源生活类模块、帮贡模块或后续确认模块；完成材料、流程、批量执行、背包处理、失败重试。
- 生活采集 / 挖矿 / 挖图：来源生活源A、采集源A、图形源A；完成采矿、采药、种植采集、挖图、路线、坐标、背包满处理。
- 单师门：来源任务源A；完成师门流程、NPC、坐标、任务识别词、接取、完成、提交、次数、失败策略。
- 帮贡五合一：来源帮贡源A；完成帮贡任务类型、帮派任务流程、NPC、地图、坐标。
- 答题题库：来源题库源A；完成龙伴行自有题库提取、统一题库格式、查询、导入导出、自动匹配预留。

## 8. 数据迁移任务

迁移目标目录：

- `data/imported/`
- `data/imported/index.json`

第一批迁移项：

- `C:\sys\aj.txt`
- 各模块 `zk.txt`
- 各模块 `001.txt`
- 各模块 `数字.txt`
- 坐标源A `自定义坐标.ini`
- 生活源A `fuben.txt`
- 生活源A `pz.ini`
- 生活源A坐标目录
- 各模块 `config.ini`

处理规则：

- 原始文件不修改。
- 复制到新项目后分析。
- 记录来源路径。
- 授权字段不进入新配置。
- 账号、密码、会员信息必须脱敏或不导入。
- 不能确定的数据标记为“待确认”，不能伪装完成。

## 9. 执行里程碑

M0 工程基础：解决方案、x86 构建、服务分层、构建运行文档。验收：一条命令可构建，软件可启动。

M1 前端目标模式：左侧绑定区、右侧横向 Tab、Tab 内胶囊 tag、首页通用配置、删除卡片概览。验收：用户能按功能组选择模式，左侧启动按钮显示当前模式。

M2 数据迁移地基：导入字库、坐标、配置样本，生成 `index.json`。验收：数据调试页可查看来源。

M3 OCR 地基：实现 `TemplateOcrService`，支持 `aj.txt`、`zk.txt`、`001.txt`、数字字库。验收：能加载字库、识别截图区域、输出识别日志。

M4 输入地基：实现 `InputService`，支持 PostMessage、SendInput、快捷键解析、公共 CD、技能间隔。验收：绑定窗口后可发送测试按键，CD 和间隔生效。

M5 P0 功能落地：窗口绑定、按键打怪、挂机返点、马贼模式、抢 NPC、自动反贼、自动和尚、自动三环。验收：每个模式有配置页、状态机、日志，并能真实驱动绑定窗口。

M6 P1 功能覆盖：跑商、材料加工、挖矿/采药/采集、挖图、单师门、帮贡、答题题库。验收：每个功能有来源、配置、状态机和接入状态。

M7 稳定性与发布：配置备份、日志导出、异常提示、崩溃保护、运行中配置变更提示、x86 发布包。验收：可交给用户直接运行，常见失败能从日志定位，不依赖敏感链路。

## 10. 固定执行方式

后续每推进一个功能，必须按以下顺序执行：

1. 查旧模块来源。
2. 复制可分析数据到 `data/imported`。
3. 更新 `data/imported/index.json`。
4. 记录来源和去授权说明。
5. 设计新配置 schema。
6. 写服务层接口。
7. 写服务层实现。
8. 写独立状态机。
9. 写 ViewModel。
10. 写 UI 配置页。
11. 构建验证。
12. 运行诊断验证。
13. 更新模块接入状态。
14. 更新迁移文档。

## 11. 不接受的完成标准

- 只有 UI，没有后端。
- 只有按钮，没有动作。
- 只有假日志，没有真实状态。
- 只有状态机名字，没有运行逻辑。
- 只说参考旧模块，没有来源路径。
- 把敏感链路带进来。
- 把多个模式混成一个大循环。

## 12. 接受的完成标准

- 有来源。
- 有配置。
- 有服务。
- 有状态机。
- 有日志。
- 有诊断。
- 能运行。
- 能复测。
- 能定位失败原因。
