# TLBB Agent 最终落地成品清单与执行任务书

> 用途：作为 TLBB Agent 后续开发的目标模式、任务清单和验收标准。  
> 核心原则：只迁移龙伴行 / 龙伴行授权数据中已有且可验证的功能逻辑；不自由发挥业务能力；不引入敏感链路；不复刻旧前端；只优化交互、配置、状态机、日志和无意义操作流程。

## 1. 产品目标

TLBB Agent 是龙伴行 辅助工具的新一代整合客户端。

第一阶段必须交付一个真实可运行的软件，而不是演示页面：

- 产品名：TLBB Agent
- 运行形态：Windows 桌面客户端
- 第一阶段目标：32 位稳定版
- 目标客户端：32 位 `Bin\Game.exe`
- 暂缓目标：64 位 `Bin64\Game.exe`
- 核心定位：现代化前端 + 旧龙伴行成熟逻辑迁移 + 统一配置 + 统一识别 + 统一输入 + 统一状态机 + 统一日志

最终成品必须做到：

- 能启动主程序。
- 能绑定游戏窗口。
- 能识别窗口标题、PID、路径、32/64 位。
- 能显示绑定角色的头像截图，方便多开辨认。
- 能保存、加载、导入、导出配置。
- 能导入旧龙伴行数据并记录来源。
- 能执行 P0 核心功能。
- 能在 UI 中覆盖历史版本 / 龙伴行已有主要功能入口。
- 每个功能都有独立配置、运行状态、日志和失败原因。

## 2. 绝对边界

以下内容不进入新项目运行链路：

- `敏感组件`
- 登录链路窗口
- 注册链路账户
- 旧账户绑定
- 旧账户充值
- 旧账户改密
- 会员链路账号验证
- 会员链路密码验证
- 旧远端授权请求
- 旧启动强制登录拦截
- 敏感链路失败弹窗
- 账号链路过期提示

处理原则：

- 敏感链路只作为迁移时的排除对象，不作为依赖。
- 如果历史执行文件 / DLL 中存在通用逻辑，只能通过静态分析、配置字段、运行态行为、释放数据、字库和坐标来还原，在新项目中重写。
- 不直接加载敏感链路 DLL。
- 不修改 `本机授权数据目录` 原始文件。
- 不处理第三方游戏平台、第三方账号系统、安全组件、反作弊、验证码或风控。

## 3. 迁移原则

旧龙伴行没有源码的模块，不声称“代码已直接搬过来”。正确迁移方式是：

- 迁移导入配置字段。
- 迁移字库模板。
- 迁移 OCR 识别词。
- 迁移图色模板。
- 迁移地图、坐标、路线。
- 迁移 NPC / 怪物 / BOSS 名称。
- 迁移流程参数。
- 迁移状态机思路。
- 迁移运行态可观察行为。
- 在 TLBB Agent 服务层中重新实现。

每个功能必须记录：

- 来源模块。
- 来源路径。
- 来源数据类型。
- 是否含授权字段。
- 去授权处理说明。
- 新项目目标格式。
- 接入到哪个服务或状态机。
- 验收方式。

## 4. 前端目标模式

TLBB Agent 是配置密集型工具软件，不采用卡片式概览菜单。

最终 UI 结构：

- 左侧固定区：
  - 窗口绑定
  - 绑定后头像截图
  - 窗口标题
  - PID
  - 进程路径
  - 32/64 位提示
  - 当前配置方案
  - 自动重连
  - 自动上号
  - 喊话
  - 当前选中模式
  - 启动 / 暂停 / 停止
- 右侧横向一级 Tab：
  - 通用配置
  - 挂机
  - 活动
  - 生活
  - 任务自动化
  - 数据调试
- Tab 内部：
  - 使用胶囊式 tag / 分段选择切换具体模式。
  - 同一时间只能选择一个主模式运行。
  - 每个模式配置独立。
- 底部全局日志：
  - 运行日志
  - 错误日志
  - 状态机日志
  - 过滤
  - 复制
  - 导出

交互要求：

- 未绑定窗口时启动按钮禁用。
- 切换模式不自动启动。
- 运行中修改关键配置时提示“下次启动生效”。
- 所有开关使用现代胶囊式点击切换。
- 所有快捷键支持录入。
- 所有坐标支持手动录入、保存、导入。
- 所有模块显示状态：未接入、部分接入、已接入、运行中、错误。

## 11. 总体验收标准

软件级：

- 主程序可启动。
- 可绑定 32 位游戏窗口。
- 可显示头像截图。
- 可保存/加载配置。
- 可导入导入数据。
- 可执行 P0 核心功能。
- 可查看和导出日志。

功能级：

- 历史版本 / 龙伴行已有主要功能在新 UI 中有入口。
- P0 功能必须真实运行，不是假按钮。
- P1 功能允许分阶段接入，但不能伪装完成。
- 每个功能都有状态：未接入、部分接入、已接入、运行中、错误。

架构级：

- UI 只负责展示、输入、命令和状态绑定。
- 核心逻辑全在服务层。
- 每个模式独立状态机。
- 配置、日志、输入、截图、OCR 都走统一服务。

迁移级：

- 不修改原始授权数据。
- 不引入 `敏感组件`。
- 不引入登录链路认证。
- 不引入账号链路 / 会员验证。
- 每个复用资产都有来源路径。
- 授权字段被剔除。

## 12. 固定执行方式

后续每推进一个功能，按以下顺序执行：

1. 查旧模块来源。
2. 复制可分析数据到 `data/imported`。
3. 更新 `data/imported/index.json`。
4. 记录来源和去授权说明。
5. 设计新配置 schema。
6. 写服务层接口。
7. 写服务层实现。
8. 写独立状态机。
9. 写 ViewModel。
10. 写 UI 配置页。
11. 构建验证。
12. 运行诊断验证。
13. 更新模块接入状态。
14. 更新迁移文档。

不接受的完成标准：

- 只有 UI，没有后端。
- 只有按钮，没有动作。
- 只有假日志，没有真实状态。
- 只有状态机名字，没有运行逻辑。
- 只说参考旧模块，没有来源路径。
- 把敏感链路带进来。
- 把多个模式混成一个大循环。

接受的完成标准：

- 有来源。
- 有配置。
- 有服务。
- 有状态机。
- 有日志。
- 有诊断。
- 能运行。
- 能复测。
- 能定位失败原因。
