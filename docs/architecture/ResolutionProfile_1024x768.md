# 1024x768 稳定基准与兼容模式策略

> 日期：2026-06-21  
> 修正结论：龙伴行第一阶段以 `32 位 Bin\Game.exe` 作为核心自动化启动门槛；`1024×768` 是导入数据和导入坐标的已校准稳定基准，不是硬性启动条件。

## 一、来源证据

敏感链路数据里确实存在大量 1024×768 锚点，但这些证据只能说明“该分辨率最稳定、导入坐标最容易复用”，不能推导为“历史版本 只能在 1024×768 运行”。

| 来源 | 证据 | 工程判断 |
|---|---|---|
| `本机授权数据目录\坐标源A\使用说明.txt` | 明确要求游戏分辨率 1024×768 | 坐标源A 坐标表按此基准优先迁移 |
| `本机授权数据目录\任务源A\使用说明.txt` | 明确要求游戏窗口 1024×768 | 单师门后续先按稳定基准校准 |
| `本机归档主来源\历史版本.dvm.exe` / `vv.dvm.exe` | 字符串包含窗口大小至少 1024 的提示 | 历史版本 本体有窗口大小约束提示，但用户实测其他分辨率可运行 |
| `本机授权数据目录\生活源A\A窗口\1.4.0.exe` | 字符串包含游戏窗口 1024×768 | 生活模块坐标优先按基准迁移 |

## 二、当前工程策略

1. `BoundGameWindow` 记录客户区尺寸 `ClientWidth/ClientHeight`。
2. `IsStableClientArea = ClientWidth == 1024 && ClientHeight == 768`，只表示当前窗口落在已校准稳定基准。
3. `IsAutomationAllowed = Bitness == X86`。非 1024×768 的 32 位窗口允许启动核心自动化。
4. `IsResolutionCompatibilityMode = X86 && !IsStableClientArea`。进入兼容模式时 UI 和日志提示风险。
5. 64 位客户端仍只允许识别、截图、基础诊断，不进入完整 P0 自动化。

## 三、兼容模式要求

非 1024×768 的 32 位窗口允许：

- 拖拽绑定。
- 显示标题、PID、路径、位数、客户区尺寸。
- 截取头像和客户区截图。
- 启动按键打怪、抢 NPC、马贼、反贼、和尚、三环等状态机。
- 使用实际客户区截图进行 OCR 区域、头像区域、点击点和坐标换算校准。

兼容模式必须提示：

- 当前客户区尺寸。
- 1024×768 是导入数据稳定基准。
- 当前按实际截图校准，识别区域和点击点可能需要人工或诊断工具修正。

## 四、当前实机验证预期

当前实机 Game 窗口示例：

```text
Screen result process=Game
Screen result path=C:\Game\TLBB\Bin\Game.exe
Screen result bitness=X86
Screen result client size=1531×955
Screen result stable client area=False
Screen result automation allowed=True
```

这表示当前窗口是 32 位 `Game.exe`，虽然不是 1024×768 稳定基准，但允许进入核心自动化，并以兼容模式运行。

## 五、后续适配方式

后续不直接粗暴缩放导入坐标表。正确路线是新增 `ResolutionProfile`：

- 标准档：`1024×768`。
- 兼容档：记录实际客户区尺寸。
- 每个档案独立维护截图区域、OCR 区域、点击点、头像区域、技能栏区域、目标名区域。
- 未校准档案允许启动，但必须保留日志提示，并优先通过诊断截图逐步校准。
