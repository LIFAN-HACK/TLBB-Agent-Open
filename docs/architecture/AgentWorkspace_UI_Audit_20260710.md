# 龙伴行 Agent 工作台前端审计

日期：2026-07-10

## 结论

当前界面已经出现“角色会话”列表和自动保存代码，但底层仍是单一当前窗口、单套配置、单套控制器。它只能在多个已绑定窗口之间切换，不能证明多个角色可独立并行运行。

本轮前端重构必须保留真实能力，隐藏或明确标记未闭环能力，不能用静态摘要代替运行状态。

## 可直接复用

- `WindowBindingService`：真实窗口绑定、进程信息、客户区尺寸和位数识别。
- `WindowCaptureService`：真实客户区和头像区域截图。
- `PerceptionHub`：L1 布局、目标血量插槽、L2 目标名称与状态条融合入口。
- `NormalHangController`：当前已实机验证的打死换怪主链。
- `AppProfileService`：整套模块配置保存、加载、窗口映射。
- `LogPanelViewModel`：日志过滤、导出、最新摘要和折叠状态。
- `ModuleCatalog`：功能接入状态来源。

## 结构性问题

1. `WindowBindingService.Current` 只有一个当前窗口。
2. 所有配置服务和自动化控制器均按单例注册。
3. `WindowSessionViewModel` 只包装窗口标题、PID、尺寸和运行状态。
4. 切换会话实际上是重新绑定全局当前窗口，不是切换独立运行上下文。
5. 配置映射键为“进程路径 + 规范化窗口标题”，尚未使用角色名称、门派、等级等身份信息。
6. 页面展示大量技术参数；正式用户需要理解内部状态机才能配置。
7. “部分接入”模块和真实可用模块出现在同一主导航，容易造成已完成功能错觉。
8. 马贼模式等页面有多项只保存配置、控制器未读取的字段。

## 本轮处理原则

- 主壳改为顶部状态栏、左侧角色会话、中间工作区、底部隐藏日志抽屉。
- 正式导航只展示具备真实服务入口的用户功能；数据调试仅开发模式显示。
- 会话卡片只展示真实数据；未识别的角色名称、等级不生成假值。
- 配置自动保存继续保留，手动“保存”从主流程移除。
- 在真正完成会话级服务作用域前，不把“全部启动”伪装成可并行启动。
- 下一阶段把配置服务、输入服务和控制器改为会话作用域，再开放 1-4 窗口独立并行。

## 接入状态

| 区域 | 当前证据 | 结论 |
|---|---|---|
| 窗口绑定 | 真实 WinAPI 与截图服务 | 可复用 |
| 普通挂机 | 真实视觉模型、输入和状态机日志 | 主线可测试 |
| 配置自动保存 | 800ms 防抖，整套方案保存 | 可复用但需角色键 |
| 会话列表 | 仅切换全局绑定 | 需要重构 |
| 多窗口并行 | 单例控制器与配置 | 未实现 |
| 角色名称/等级识别 | 当前模型无玩家名称/等级插槽 | 未实现，不显示假值 |
| 马贼/BOSS | 静态诊断为模拟识别，实机闭环缺失 | 隐藏高级配置并继续接入 |
| 数据调试 | 开发工具 | 正式模式隐藏 |
