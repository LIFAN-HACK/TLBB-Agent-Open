## 1. 最终产品定义

TLBB Agent 是面向多角色窗口的纯视觉 AI 辅助控制台，不是坐标脚本编辑器。

品牌展示统一为主标题 `TLBB Agent`、副标题“新一代的AI智能辅助系统”。正式界面使用天龙八部主题标志与武侠海报背景；用户数据使用 `%APPDATA%\TLBB Agent`，首次启动只复制旧目录中缺失的配置，不覆盖、不迁移旧日志、不删除旧目录。

玩家负责：

- 绑定角色窗口。
- 选择角色、模式和目标。
- 修改少量可理解的角色配置。
- 管理名单、顺序和高层开关。
- 查看运行状态和异常。

后端负责：

- 角色、门派、等级、地图、目标、队伍和背包识别。
- 所有判断、计时、冷却、选怪、寻路、战斗、治疗和恢复。
- 技术参数、模型参数、坐标、识别区域、置信度和重试策略。
- 各模式独立状态机、运行快照和可回放日志。

硬原则：

> 前端只收集用户意图、管理角色级配置、发送高层命令并展示后端状态；识别、判定和执行全部在后端完成。

## 2. 不进入正式产品的内容

正式用户界面不得展示：

- X/Y 坐标、点击位置、底部偏移或区域框。
- 输入通道、PostMessage、SendInput、客户端点击等执行方式。
- 扫描间隔、点击延迟、重试次数、公共 CD 毫秒值。
- OCR 区域、模板路径、样本路径、阈值、置信度和模型校准。
- PID、进程路径、分辨率等无助于玩家操作的技术信息。
- 旧步骤队列、脚本动作编辑器和 Mock 数据。
- “AI 将会……”“前端只负责……”等开发说明。
- 后端未闭环却能够启动的假开关。

以下能力只允许进入隐藏开发工具：

- 识别预览与样本采集。
- 模型诊断与回放。
- 原始运行快照和技术日志。
- 兼容性参数与旧数据导入诊断。

正式版本默认隐藏开发工具和数据调试入口。

## 3. 正式信息架构

### 3.1 主框架

视觉结构只保留两个层级：

1. 应用基础层：品牌、窗口管理、角色会话，以及左下角用户登录状态和账户菜单。
2. 控制台层：横向一级 Tab、二级模式、当前功能配置和默认收起的运行记录。

Tab、角色标题、内容区和运行记录属于同一个控制台，不再分别套独立主面板，也不用贯穿横线或竖线分割；层级依靠背景、留白和必要圆角表达。输入框、按钮等交互控件仍保留清晰焦点边界。

一级 Tab：

1. 角色设置
2. 挂机
3. 活动
4. 生活
5. 任务
6. 答题

“角色设置”就是通用配置首页，不增加概览仪表盘或纵向功能菜单。

左下账户入口通过 `IUserSessionService` 读取登录态、显示名和权益入口。当前未接入真实账户后端时必须显示“未登录”，登录按钮保持不可用，不模拟登录成功。

### 3.2 角色会话

最终支持 1–4 个角色窗口，每个角色独立拥有：

- 角色身份和头像。
- 当前方案与配置修订号。
- 启动、暂停和停止状态。
- 各模块状态机。
- 喊话冷却、巡逻进度、杀怪数和副本阶段。

配置属于角色，不属于全局软件。

角色配置流程：

1. 后端绑定窗口并识别角色名、门派、等级和可用区服信息。
2. 精确匹配历史身份时自动加载角色方案。
3. 低置信度、重名或证据冲突时返回 `NeedsConfirmation`。
4. 玩家只选择已有角色方案或新建角色，不手动填写识别结果。
5. 所有修改自动保存，不提供“保存”按钮。

当前边界：现阶段只有多窗口发现和全局单窗口切换，尚不能宣称 1–4 个角色独立并行。前端在会话级配置、控制器和输入隔离验收前不得提供“全部启动”或多卡片同时运行。

## 4. 角色通用配置首页

首屏只保留玩家确实需要配置的内容。

### 4.1 基础配置

- 门派。
- 选怪 / 切换目标快捷键。
- 内置挂机快捷键。
- 玩家操作保护：只检测玩家鼠标操作。
- 玩家操作后的暂停时长。

门派应在绑定窗口后由后端自动识别；手动选择只作为识别未就绪或需要确认时的兜底。

### 4.2 角色恢复配置

- 角色回血。
- 角色回蓝。
- 宠物回血。
- 宠物口粮。
- 血祭回蓝。
- 共生回血。

恢复项使用紧凑数字输入，不使用滑杆。识别和触发判断由后端完成。

### 4.3 技能预设过渡期

技能预设暂时保留，用于后端尚未自动识别技能时的兼容：

- 启用状态。
- 技能名称。
- 快捷键。

技能识别闭环后，前端逐步收敛为“已识别技能数量、状态和异常”，不继续扩展传统脚本参数。

## 5. 挂机中心

二级模式：

1. 挂机打怪
2. BOSS 模式
3. 副本模式
4. 自动清包
5. 材料加工

### 5.1 挂机打怪

战斗方式只有：

- 内置挂机
- 按键打怪

共同规则：

- 不提供“自动切怪”开关，默认打死换怪。
- 不在前端展示目标扫描、识别阈值、坐标或执行延迟。
- 自动返点对两种方式都可用。

内置挂机：

- 固定点运行。
- 战斗行为由游戏内挂机接管；近战角色也按游戏内挂机的远程选怪表现运行，前端不再增加追怪或巡逻配置。
- 只显示内挂快捷键、监控状态和自动返点。
- 后端必须持续监控内挂是否意外停止，并按状态恢复，不能盲目重复按键。
- 监控未接入时显示“未就绪”并禁止选择或启动。

按键打怪：

- 默认自动寻找并切换目标。
- 支持定点巡逻和多个记录点位；前端只显示点位名称、顺序和状态，不显示坐标。
- 支持攻击玩家开关；后端最终攻击门禁必须执行该策略。
- 门派为峨眉时显示给自己 / 给队友加血。
- 支持杀怪数监控、阈值和回城 / 下线动作。
- 杀怪数由后端提供权威计数：优先采用经版本校验的只读内存来源，无法稳定读取时退化为战斗事件或视觉计数；前端只显示计数、来源状态和阈值结果。

自动返点：

- 土灵珠返点。
- 自动寻路。

玩家只选择方式；触发原因、地图识别、路径和失败降级由后端处理。

### 5.2 BOSS 模式

- 固定使用按键打怪，不显示战斗方式。
- 主页面只保留开关、状态和白名单入口。
- 白名单分系统 BOSS 库与角色自定义名单。
- 支持截图添加当前目标，由后端识别后返回候选，玩家只确认或取消。
- 最终攻击前必须执行白名单硬门禁。
- 发现刷新目标后进入极速选怪和爆发策略。
- 旧马贼模式、跟随、路线和坐标字段不得改名复用。

### 5.3 副本模式

- 固定使用按键打怪。
- 玩家不配置目标、坐标、步骤或怪物顺序。
- 前端只显示状态、当前副本、当前阶段和异常。
- 后端通过地图识别加载版本化副本规则库。

首批规则：

- 燕子坞硬门禁：先击杀岳老三；岳老三死亡后云中鹤与叶二娘才进入候选；云中鹤死亡后段延庆才允许出现。当前明确优先级为岳老三 → 云中鹤 → 叶二娘，段延庆与叶二娘的最终先后必须由实测样本确认后再写入版本库。
- 缥缈峰：桑土公阶段将“碧鳞僵尸”加入硬排除名单，不得攻击。

### 5.4 自动清包

- 属于挂机生命周期。
- 支持月卡清包和回城清包。
- 回城地点：洛阳、苏州、大理、楼兰。
- 只允许出售明确名单中的物品。
- 未知物品默认保护。
- 后端未具备安全出售闭环前，只生成候选，不执行出售。

### 5.5 材料加工

- 只保留启用状态和加工周期。
- 背包识别、材料判断和全部加工由后端完成。

## 6. 喊话

喊话归入生活 Tab，配置绑定当前角色。

前端：

- 多个长条喊话项。
- 自动编号“喊话 1、喊话 2……” 。
- 新增、删除、拖拽排序。
- 每条独立开关、频道和内容。
- 总开关和运行状态。

频道：

1. 附近频道
2. 世界频道
3. 同城频道
4. 帮派频道
5. 同盟频道
6. 门派频道
7. 队伍频道

后端：

- 按可见顺序发送。
- 世界频道固定冷却 180 秒。
- 冷却按角色会话隔离并跨暂停、重启持久化。
- 频道路由未就绪时不得发送任何聊天输入。

## 7. 活动、生活、任务和答题

### 7.1 活动

只保留玩家能理解的模式和高层开关：

- 自动反贼
- 自动宵小
- 自动和尚

玩家选择自动找点或手动带到点位。刷新时间、地图、NPC、屏蔽玩家、识别和点击全部由后端处理。

### 7.2 生活

- 挖图
- 采矿
- 采药
- 跑商
- 喊话

未接入能力只显示简洁状态页，不展示旧坐标、路线和 Mock 配置。

### 7.3 任务

- 师门任务
- 帮贡任务
- 新鸳鸯蝴蝶梦
- 百变脸谱
- 一千零一个愿望

取消步骤编辑器。前端只允许选择任务和拖拽执行顺序，后端负责识别任务类型、规划和执行。

师门任务提供任务类型策略，不展示执行步骤：

- 打怪。
- 送信。
- 抓宝宝。
- 买物品 / 药品。

玩家关闭某一类型后，后端识别到该类型应按策略放弃任务；例如关闭“买物品”后，接到购买任务自动放弃。

### 7.4 答题

独立一级 Tab，只显示：

- 开启 / 关闭。
- 剩余次数或服务状态。
- 当前答题状态。

后端未接入题库和答题执行器前保持“未就绪”。

## 8. 日志与状态

日志使用底部抽屉，默认收起，不遮挡角色或主工作区。

正式用户只看：

- 当前动作。
- 状态变化。
- 冷却或进度。
- 可处理的异常。

原始识别结果、模型耗时、坐标、输入通道和调试堆栈进入隐藏开发工具。

所有运行状态必须来自后端快照，不允许 ViewModel 根据开关自行推断“运行中”。

---

## 9. 后端架构硬边界

### 9.1 角色会话隔离

所有配置、命令和运行快照显式携带：

- `RoleSessionId`
- `CharacterProfileId`
- `ExpectedRevision`

每个角色独立拥有配置快照、控制器、状态机、取消令牌、输入冷却和模块进度。

需要前台激活的输入通过全局仲裁器串行执行；可后台执行的输入仍按窗口和会话隔离。

### 9.2 Capability 驱动前端

后端向前端提供结构化能力状态：

- `Unavailable`
- `NotReady`
- `Ready`
- `Running`
- `Paused`
- `Error`

只有 `Ready` 的能力才能启用启动或配置入口。错误必须返回用户可理解的阻塞原因。

### 9.3 模式独立

挂机、BOSS、副本、活动、生活和任务不得混成一个大循环。每个模式都有独立状态机、契约、日志和回放测试。

## 10. 旧资产与安全迁移边界

允许迁移：

- 字库、模板和识别词。
- 地图、NPC、怪物和副本规则数据。
- 旧路线和坐标数据，但只能作为后端数据，不能重新暴露给玩家。
- 已验证的状态机行为和异常处理经验。

禁止引入：

- 旧登录、注册、充值、会员、远端授权和账号链路。
- 旧敏感运行组件。
- 未验证地址、偏移或内存结构。
- 通过旧 DLL 直接恢复业务链路。

原始归档目录只读；任何迁移必须记录来源、目标、去除字段和风险。

### 11.1 已落地

- 横向一级 Tab 和 Tab 内胶囊式二级模式。
- TLBB Agent 品牌名称、透明 LOGO、多尺寸 Windows 图标和右侧工作区武侠海报背景。
- 通用配置首页。
- 正式通用配置 ViewModel 只持有角色级声明式配置；坐标、点击测试和识别采样兼容代码已退出正式编译路径。

- 喊话长条队列、七频道、单条开关和拖拽排序。
- 普通挂机默认打死换怪。
- 内挂未就绪硬门禁。
- 按键挂机的条件化状态入口。
- BOSS 和副本极简状态页。
- 自动清包与材料加工的高层配置页；清包仍强制候选模式和未知物品保护。
- 活动中心三项配置页、日常任务拖拽排序页和答题助手极简状态页。

- 喊话和专项模式按真实 capability 标记。
- 16 个正式 `FeatureKey` 已集中定义；成品路由不再把 BOSS、清包、材料、生活和任务映射到旧控制器键。
- 清包、材料加工在后端未就绪时禁止开启执行意图；挂机本地状态只表述“配置完整 / 待配置”。
- 用户日志已有中央强制隐私策略：显式 `User` 也会重新检查，路径、模型/引擎、异常文本、句柄/PID、坐标/ROI、密钥、内部配置键、样本和置信信息不得进入用户摘要。
- 正式运行记录只展示“时间 / 状态 / 事件”，不展示窗口标识、内部模块或 Trace；复制与导出仅包含屏幕中已经脱敏的最多 800 条记录。
- 崩溃反馈只显示反馈编号并写入无堆栈的安全事件记录；原始战斗遥测默认关闭，Release 构建不可写入，仅 Debug 构建在显式开发环境变量开启后可用。
- 暂停和停止命令按真实运行态启用；非当前窗口卡不再继承全局控制器状态。
- 底部日志抽屉。
- Release 构建编译期移除开发工具入口；环境变量不能重新打开数据调试页。
- 角色会话容量、HWND 所有权、身份冲突、命令幂等和关闭语义已有管理器与专项测试骨架，但尚未接入主界面。

## 12. 实施顺序

### P0：会话与能力地基

1. 将 `IRoleSessionManager` 接入主应用。
2. 配置、控制器、输入和自动保存改为角色会话作用域。
3. 建立角色身份识别、确认和历史方案映射。
4. 建立 capability 与运行快照协议。
5. 完成 1–4 会话并发隔离测试。

### P1：普通挂机闭环

1. 喊话频道执行器与持久冷却。
2. 内挂看门狗。
3. 定点巡逻和点位高层接口。
4. 杀怪计数。
5. 自动返点。
6. 峨眉队伍区域与治疗状态机。

### P2：专项模式

1. BOSS 白名单、截图确认、硬门禁和极速执行。
2. 副本识别、规则库和阶段推进。
3. 活动状态机。
4. 安全清包和材料加工。

### P3：生活、任务与答题

按真实后端能力逐项开放，未闭环前保持极简“未就绪”状态页。

## 13. 完成定义

一个功能只有同时满足以下条件才算完成：

- 有角色会话级配置契约。
- 有独立后端状态机或服务。
- 有 capability 和结构化运行快照。
- 前端只显示玩家需要的配置和状态。
