# TLBB Agent 最终成品任务清单

本文稿用于固定 TLBB Agent 的目标模式、实现边界和验收标准。后续开发按本文推进，不自由发挥，不引入敏感链路，不复刻旧 UI。对外产品名、窗口标题和程序集产品名统一为 `TLBB Agent`。

## 一、产品目标

项目名：TLBB Agent

第一阶段目标：交付一个真实可运行的 32 位稳定版历史版本 功能迁移客户端。

核心原则：

1. 只迁移历史版本 与敏感链路数据目录中已有的成熟功能、配置、字库、坐标、流程和状态机思想。
2. 不引入登录链路、注册链路、充值链路、账号链路绑定、敏感链路 DLL、旧远端授权请求。
3. 不引用 `敏感组件` 敏感链路。
4. 不做 EXE patch 工具。
5. 不做第三方登录、安全组件、反作弊、验证码或服务器风控绕过。
6. 前端只优化交互，把旧 UI 中复杂、重复、无意义的操作合并为更清晰的配置与模式选择。
7. 业务逻辑必须来自服务层和状态机，不能写在 WPF 按钮事件或页面 code-behind 中。

## 二、最终软件形态

主界面形态：

- 左侧固定区：窗口绑定、头像截图、角色/窗口信息、当前方案、启动/暂停/停止、运行摘要。
- 顶部横向 Tab：通用配置、挂机、活动、生活、任务自动化、数据调试。
- 每个 Tab 内使用胶囊式模式 Tag/Segment 切换。
- 同一时间一个窗口只允许运行一个主模式。
- 底部运行记录：默认收起，只显示脱敏后的时间、状态和用户事件；支持复制、导出、清空。

当前 M1 验证记录：

## 三、基础服务必须完成

1. `AppInitService`
   - 初始化 `%APPDATA%\TLBB Agent`
   - 初始化 profiles/logs/data/ocr/backups/legacy-imports
   - 不做远端登录认证

2. `WindowBindingService`
   - 拖拽绑定窗口
   - 后端读取句柄、PID、标题、进程路径；正式前端只显示可理解的窗口候选与绑定状态
   - 判断 32 位 / 64 位
   - 64 位提示“当前阶段优先支持 32 位客户端”
   - 检测客户区尺寸；第一阶段 `32 位` 是核心自动化启动门槛，`1024×768` 仅作为已校准稳定基准，其他尺寸进入兼容模式并提示校准风险
   - 支持解绑、重新绑定、多窗口预留

3. `WindowCaptureService`
   - 窗口截图
   - 客户区截图
   - 区域截图
   - 绑定后左侧显示角色头像区域截图
   - 给 OCR 服务提供输入图像

4. `TemplateOcrService`
   - 解析 `aj.txt`、`zk.txt`、`001.txt` 类点阵字库
   - 识别固定文字、怪名、NPC、地图、状态提示
   - 支持调试预览

5. `InputService`
   - 支持 F1-F12、数字键、组合键
   - 支持 PostMessage / SendInput 适配
   - 支持公共 CD、技能间隔、无效窗口保护

6. `StateMachineEngine`
   - 所有模式都通过独立状态机运行
   - 不允许把普通挂机、马贼、抢 NPC、反贼、和尚、三环写成一个大循环

7. `ProfileConfigService`
   - 命名保存、加载、导入、导出
   - 自动备份、版本迁移
   - 按窗口、角色、模式保存

8. `RuntimeLogService`
   - 全部日志统一出口
   - 内部诊断与用户记录强制分层；用户记录不展示窗口标识、模块名、模型细节、路径、坐标、异常原文或堆栈
   - 用户复制和导出只包含已脱敏的当前可见记录

9. `LegacyDataAdapter`
   - 只读导入导入数据
   - 记录来源路径
   - 转换为新项目统一 JSON/配置结构
   - 不修改原始授权数据目录

## 四、P0 必须交付功能

1. 窗口绑定
   - 来源：`历史版本`
   - 验收：能拖拽绑定 32 位 `Bin\Game.exe`，显示标题/PID/路径/位数，绑定后显示头像截图，启动按钮只在绑定后可用。

2. 普通挂机 / 按键打怪
   - 来源：`历史版本`
   - 验收：技能循环、技能间隔、公共 CD、快捷键自定义、峨眉加血、打死换怪、只打指定目标、日志可追踪。

3. 挂机返点
   - 来源：`历史版本` + `坐标源A` 坐标数据
   - 验收：坐标录入、多坐标保存、定点返点、土灵返点、死亡返点、卡点恢复、按角色/窗口/方案保存。

4. 马贼模式
   - 来源：`历史版本` 为状态机主来源，`坐标源A` 为坐标补充，`跟随源A` 为双开/队员跟随来源
   - 验收：独立 `HorseBanditModeController`，自动跟随队长、识别马贼目标、攻击、丢失恢复、回到跟随、异常日志。

5. 抢 NPC
   - 来源：`历史版本` “抢抢”页签
   - 验收：拆分 `NpcTargetingService` 与 `NpcActionService`，支持抢反、抢小、抢小丹、抢小2、抢和尚、抢箱子、抢上架、高甲卫、高甲卫23，支持扫描间隔、点击间隔、失败重试；抢小支持“刷新窗口高频识别 + 上下文快抢”双通道。

6. 自动反贼
   - 来源：`历史版本`
   - 验收：地图选择、坐标录入、路线执行、目标识别、进战/结束检测、异常恢复。

7. 自动和尚
   - 来源：`历史版本`
   - 验收：独立状态机，地图/坐标配置，路线执行，和尚目标识别，活动结束前停止或退出。

8. 自动三环 / 副本
   - 来源：`历史版本` 副本设置
   - 验收：老三环、新三环、次数、队伍编号、左桥、2 号 boss 站位、执行脚本、结束清包、完成后衔接其他任务。

## 六、每个功能的开发流程

每个功能按同一流程交付：

1. 只读分析旧模块来源。
2. 记录来源路径和数据格式。
3. 提取可复用配置、字库、坐标、关键词、状态流。
4. 转换为新项目统一模型。
5. 写服务层接口和实现。
6. 写独立状态机控制器。
7. 写 ViewModel 和 WPF 页面。
8. 写诊断工具命令。
9. 跑构建、诊断、WPF 启动、授权链扫描。
10. 更新运行文档。

## 七、验收标准

一个功能只有同时满足以下条件，才算完成：

1. UI 可配置，不只是空页面。
2. 配置能保存和加载。
3. 运行必须走服务层，不直接写按钮事件逻辑。
4. 状态机可启动、停止、记录当前状态。
5. 有诊断命令可以离线验证主要逻辑。
6. 日志能说明正在做什么、失败原因是什么。
7. 不引用登录链路、敏感链路、`敏感组件` 或旧远端授权 API。
8. 不修改 `本机授权数据目录` 原始文件。
9. 真实窗口能力必须优先支持 32 位客户端。

## 九、下一阶段执行顺序

1. P0-1 窗口绑定实机校准：绑定真实 32 位 `Bin\Game.exe`，校准头像区域截图，确认 64 位提示、解绑、重新绑定和日志。

3. P0-3 挂机返点实机闭环：继续校准地图名 OCR；用 WPF 主界面实际点击“读取当前坐标”；验证定点返点、土灵返点、死亡返点和卡点恢复在真实窗口中的运行日志；研究坐标到地图点击点换算或分段路线点击策略。

7. 每完成一个模式都必须跑构建、诊断、WPF 启动、授权链扫描，并更新迁移文档和运行文档。
