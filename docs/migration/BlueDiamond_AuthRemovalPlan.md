# 蓝钻自有旧登录认证移除计划 (BlueDiamond_AuthRemovalPlan)

> 迁移阶段文档 · 仅针对**蓝钻开发组自有旧客户端**的旧登录认证
> 生成日期：2026-06-20
> 状态：计划（第一轮，未执行任何移除）

---

## 0. 严格边界（再次声明）

✅ **允许移除（仅限蓝钻自有旧客户端内部）**：
登录使用、注册账户、账户绑定、账户充值、账户改密、会员账号验证、会员密码、旧授权 DLL 调用、远端授权请求、旧账号验证 API、启动强制登录拦截、授权失败弹窗、账号过期提示。

❌ **绝不触碰**：
第三方游戏（天龙八部）登录、第三方平台账号、第三方安全/反作弊组件、验证码、服务器风控、任何不属于蓝钻自有软件的保护机制。

⚠ 全部旧客户端**无源码**（32 位加壳二进制）。因此本计划的"移除"= **在新项目中不重建旧登录**，并把旧登录里夹带的**本地初始化逻辑迁移到 `AppInitService`**；对二进制本身**不做 patch**（产品文档 §9.2）。

### 1.1 全局共性入口

```

P_UserReg    P_CardReCharge  P_ChangePwd
```

## 3. "不能直接删、需先隔离"的混合逻辑

旧客户端常把登录与本地初始化耦合在启动流程里。以下逻辑**与登录混在一起，但本身无害且必要**，必须先识别再分离：

| 混合逻辑 | 旧位置 | 迁移目标 | 注意 |
|---|---|---|---|
| 配置目录/文件初始化 | 旧启动登录流程内 | `AppInitService` | 去掉其中的授权检查分支 |
| 日志目录初始化 | 同上 | `AppInitService` → RuntimeLogService | - |
| 字库加载(aj.txt/zk.txt) | 旧授权后才加载 | `AppInitService` + LegacyDataAdapter | **解除"授权通过才加载字库"的依赖** |
| 插件/运行库释放 | 旧授权流程释放到 C:\sys | `AppInitService`(重写到 APPDATA) | 不再写系统盘根目录 |
| 游戏目录(`Game.exe`)读取 | config `[路径] 游戏目录` | WindowBindingService/Profile | 保留，与登录无关 |
| 自动上号账号读取 | `账号目录`/`账号.txt` | 后续安全账号模块 | **必须脱敏存储，绝不明文** |

**隔离原则**：先把初始化逻辑搬到 `AppInitService`，确认新启动链路在**无任何授权检查**下能完成「建目录→加载字库→就绪」，再彻底丢弃旧登录分支。

## 4. "只有 EXE 无源码"的迁移策略（全部模块适用）

产品文档 §9.2 已定调，落地为：

1. **不以二进制 patch 为主路线**。不修改、不 crack 原始 EXE/DLL。
2. **优先提取自有可授权数据**：字库、坐标、config 字段、题库、物品清单、路线 → 进 `data/imported`。
3. **在新后端重写功能**：用 .NET 重新实现窗口绑定/截图/识别/按键/状态机，数据来自第 2 步。
4. **临时兼容层（仅在必要时）**：若某能力短期无法重写而必须临时复用旧 32 位运行库，须：
   - 单独记录在 `docs/migration` 并标注风险；
   - 仅服务蓝钻自有授权模块；
   - 运行在 x86 worker 进程内隔离；
   - 列为技术债，排期替换。
   - 第一阶段**默认不走此路**。

## 5. 移除验收标准（对齐产品文档 §9.3）

- [ ] 新客户端启动不显示登录/注册/充值/改密界面
- [ ] 不依赖任何旧会员账号即可进入主界面
- [ ] 所有业务通过本地 Profile 管理，无远端授权请求
- [ ] 字库/题库/路线/模板在**无授权门控**下正常加载
- [ ] 不出现"登录失败/授权过期/会员账号错误"类提示
- [ ] 无任何明文账号密码落盘（旧 `账号.txt` 内容不入新库）
- [ ] `AppInitService` 在干净环境下可独立完成初始化
