# TLBB 视觉插槽 V2 接入说明（R6 最终交付）

## 1. 结论

当前交付采用三层结构：

1. **核心 L1 ONNX**：从全屏定位目标框、玩家框、宠物框、技能栏和小地图。
2. **L1-Aux 面板定位**：从全屏定位材料、月卡、商店、背包、钱庄、死亡、NPC 目的地、自动寻路和确认框。
3. **L2 框内插槽**：只读取 L1 crop，判断血蓝量、CD、技能身份、怪物点、地图坐标、按钮语义并返回屏幕坐标。

自动化脚本只能执行 `slot_action_planner.py` 返回的 `action=click`。任何 `unknown`、低置信度、非法动作或未知出售物品都必须 `noop`。

实现方式不是单一模型：

| 层级 | 实现 | 职责 |
| --- | --- | --- |
| 核心 L1 | 训练后的 YOLO/ONNX | 从全屏定位七类框，并返回当前分辨率的屏幕坐标 |
| L1-Aux | 多尺度模板定位 | 定位材料、月卡、商店、背包、NPC 等固定面板 |
| L2 固定状态 | 图色/多模板匹配 | 血蓝比例、技能身份、CD、宠物状态、小地图怪点 |
| L2 文字 | 像素数字模板/OCR | 地图坐标、目标名、目的地和面板文字 |

## 3. 运行顺序

```text
全屏截图
  -> 核心 L1 ONNX / L1-Aux
  -> 取 detection.bbox 内 crop
  -> 对应 L2 worker
  -> slot_action_planner
  -> action=click 才允许执行
  -> 下一帧复核状态变化
```

不要把全屏图直接传给 L2。即使 CLI 支持 `--bbox`，worker 也会先按 bbox 裁剪再分析。

## 4. 坐标契约

L1 输出屏幕坐标：

```json
{"class_name":"minimap","confidence":0.91,"bbox":[2328,31,2568,259]}
```

L2 同时返回 crop 坐标和屏幕坐标：

```text
screen_x = l1_bbox.x1 + crop_x
screen_y = l1_bbox.y1 + crop_y
```

窗口模式下不能假设 HUD 从 `(0,0)` 开始。已覆盖的客户区偏移包括：

- `2560x1440`：客户区起点 `(0,24)`
- `2576x1408`：客户区起点 `(8,31)`，客户区大小 `2560x1369`

## 5. 调用示例

### L1-Aux 定位材料面板

```powershell
python train/artifacts/l1_ui_aux/ui_aux_locator.py `
  --image screenshot.png `
  --classes material_panel
```

### 玩家血蓝量

```powershell
python train/artifacts/l2_slots/l2_slot_worker.py `
  --mode player `
  --image screenshot.png `
  --bbox 0,0,240,66
```

当 `mp_ratio < 配置阈值` 时，再检查宠物回蓝技能是否 `identity_state=matched` 且 `cd_state=ready`。

### 小地图怪物点

```powershell
python train/artifacts/l2_slots/l2_slot_worker.py `
  --mode minimap `
  --image screenshot.png `
  --bbox 2328,31,2568,259
```

`nearby_monster_state` 必须按三态处理：

| 状态 | 脚本动作 |
| --- | --- |
| `present` | 允许找怪/攻击轮询 |
| `absent` | 停止找怪轮询 |
| `unknown` | 保持上一安全状态或 `noop` |

### 地图坐标

```powershell
python train/artifacts/l2_slots/minimap_coordinate_worker.py `
  --image screenshot.png `
  --bbox 2328,31,2568,259
```

成功输出：

```json
{
  "state":"confirmed_candidate",
  "recognition_engine":"pixel_template",
  "coordinate":{"x":87,"y":125,"text":"87,125"},
  "coord_text_screen_roi":[2431,67,2503,81]
}
```

坐标以游戏固定 0–9 像素字库为主，Tesseract 仅降级使用。

### 材料/月卡/商店等面板

先传入 L1-Aux 面板框，再指定业务动作：

```powershell
python train/artifacts/l2_ui_panels/ui_panel_slot_worker.py `
  --image screenshot.png `
  --panel-class material_panel `
  --bbox 1091,308,1422,746 `
  --requested-action manufacture `
  --l1-confidence 0.92
```

只有以下条件同时成立才会返回 `primary_button_candidate`：

- L1 身份置信度足够；
- 动作在该面板白名单内；
- OCR 或经批准的框内控件模板确认；
- 商店出售时额外满足 `item_policy=allow_sell`。

通用 `confirm_dialog` 和 `npc_destination_panel` 保持 OCR-only，避免只凭按钮外观误点。

### 动作规划

```powershell
python train/artifacts/l2_slots/slot_action_planner.py policy `
  --slot-result result.json `
  --policy-mode material
```

执行层只接受：

```json
{"ok":true,"action":"click","point":[1344,724]}
```

`noop`、`stop_find_monster_polling`、`allow_find_monster_or_attack_loop` 都是状态机命令，不是鼠标点击。

## 6. 功能策略

### 玩家与宠物

- 玩家 HP/MP：框内图色比例。
- 宠物出战：存在 `pet_status_panel` 且 L2 命中；L1 框缺失视为 `resting_or_absent`。
- 低置信度宠物状态不自动召回或点击。

### 技能

- 玩家技能仅处理底栏 `F1–F7` 的 CD 和按键释放。
- 血祭可能在宠物主动槽 1 或槽 2。
- 血祭/高级血祭归为回蓝；共生/高级共生归为回血。
- 图标身份和 CD 分开判断，模板不负责回答 CD。

### 清包

- 视觉层负责商店/背包/钱庄框、按钮坐标和物品名 ROI。
- 脚本层负责 `keep/sell` 白名单。
- `unknown`、OCR 失败、未配置物品一律禁止出售。

### 自动寻路

- 目的地面板和安全确认框由 OCR 确认。
- 坐标连续帧用于判断到达、继续或卡住。
- 点击后必须复核地图名或坐标发生预期变化。

## 8. 运行时配置与剩余风险

1. 玩家 HP/MP 阈值、技能优先级和 CD 策略由脚本配置，不写死在模型中。
2. 清包必须提供项目专用 `keep/sell` 白名单；未配置或 OCR 不确定的物品禁止出售。
3. 新面板样本多为连续录制，当前保留已验证的 L1-Aux 模板定位；补足独立会话和原生分辨率后可再训练辅助 ONNX。
4. 回城目的地样本较少，必须保留 OCR 和点击后状态复核。
5. 当前指标只覆盖已审阅的游戏版本和 UI；未来皮肤、缩放方式或版本更新需要重新回归。
