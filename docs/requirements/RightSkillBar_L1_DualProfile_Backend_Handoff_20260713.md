# 右侧技能栏 L1 双档模型后端接入任务书

## 1. 结论与范围

右侧两列技能栏已有独立 L1 检测模型，可进入后端候选接入阶段。

本文仅替代旧文档中“`right_skill_bar` 尚不可用、必须保持 unknown/noop”这一项。旧文档关于技能资产、L2、CD、策略和安全动作的其他约束继续有效。

模型和数据由视觉模型任务维护；本任务要求后端完成真实 ONNX Runtime 接入、坐标映射、双档融合、槽位重建和回归测试。不要在后端仓库重新训练或改写视觉资产。

## 3. 架构要求

1. 新建或复用独立的 `IRightSkillBarDetectService` 类服务。
2. 不要把该权重伪装成现有 7 类 L1 模型的新类别，也不要修改原 7 类模型的类别表。
3. 服务内部维护两个固定 batch `1` 的 ONNX 会话：640 和 1280。
4. 输出至少包含：`Available`、`Confidence`、`SourceProfile`、`BoundingBoxPx`、`GeometryGatePassed`、`Slots`、`ModelVersion`。
5. 两档都无合法候选时返回 `Available=false`，上层语义为 `unknown/unavailable`。
6. 模型服务不得直接发出键盘或鼠标动作。

建议数据流：

```text
完整游戏客户区帧
  -> 640 ONNX + 1280 ONNX
  -> 各自解码/NMS/映射回原图像素
  -> 源像素几何门控
  -> 选择最高置信合法候选
  -> 首槽局部边框吸附
  -> 固定几何重建 2 x 10 槽位
  -> L2 图标身份与 CD 状态
  -> 策略层
  -> 允许时才执行，否则 noop
```

## 4. 推理与双档融合

预处理必须与 Ultralytics YOLOv8 一致：保持宽高比 letterbox、填充值 `114`、BGR 转 RGB、`NCHW float32`、除以 `255`。

候选建议参数：

- 模型候选置信度：`0.001`
- NMS IoU：`0.70`
- 每档最大候选：`20`
- 业务接纳置信度：`0.25`

预测框反映射到原始客户区像素后，执行以下硬门控：

```text
52 <= width_px <= 105
245 <= height_px <= 440
-6 <= frame_width - x2 <= 65
y1 >= 0
y2 <= frame_height + 4
confidence >= 0.25
```

把两档通过门控的候选合并，选择置信度最高者；同一帧最终只能输出一个技能栏。门控不通过的高置信候选也必须拒绝。

经验证的基线是每帧运行两档。若做“1280 优先、无合法框再运行 640”的性能优化，必须在第 8 节全部样例上重新验收并记录差异。

## 5. 20 槽位坐标重建

固定源像素几何：

```text
columns = 2
rows = 10
slot_width = 32
slot_height = 32
column_pitch = 44
row_pitch = 35
full_grid_width = 76
full_grid_height = 347
```

模型框左上角只作为首槽近似锚点。后端应在其周围 `+-6 px` 内搜索 32 px 外框证据，得到吸附后的 `(x0, y0)`，再计算：

```text
slot_x = x0 + col * 44
slot_y = y0 + row * 35
slot_w = 32
slot_h = 32
```

禁止按模型框宽高平均切成 `2 x 10`。技能栏可能稀疏、底部为空或靠画面边缘，平均分割会造成图标裁切并污染 L2。

每个槽位需输出：行列索引、原图像素框、是否完整在客户区内、边框吸附置信度。越界或证据不足的槽位为 `unknown`，不能交给动作层。

## 6. L2 与动作安全边界

- L2 图标识别只读取单槽 crop，并与技能资产库比对。
- CD 判断独立读取灰罩、数字覆盖或其他已定义状态，不由 L1 负责。
- “识别到槽位”不等于“允许释放”。
- 仅当技能身份已知、CD 明确 ready、策略允许、当前游戏状态允许时，才可生成键盘或鼠标动作。
- 身份、CD、槽位、策略任一为 unknown 时统一 `noop`。

## 7. 日志与可观测性

每次候选判断至少记录：

- 模型版本及两份 ONNX SHA256。
- 原始帧宽高。
- 每档候选数量、最高置信度和候选框。
- 几何门控通过/拒绝及具体原因。
- 最终选择的 profile、置信度和原图像素框。
- 槽位吸附结果和完整槽位数量。
- 最终是识别、unknown 还是 noop，不记录原始敏感画面。

## 8. 验收基线

视觉资产已有以下离线结果：

- 单档 1280：Precision `1.0000`、Recall `0.9654`、mAP50 `0.9886`、mAP50-95 `0.9667`。
- 双档 ONNX V2 独立盲测：`33/33`。
- 双档 ONNX 全人工窗口回归：`40/40`。

验收素材：

- `diagnostics/v2_test_onnx/`
- `diagnostics/all_manual_onnx/`
- `review/representative_full_index.json`
- `review/representative_full/`

后端必须增加自动化测试，至少覆盖：

1. 启动时模型文件与哈希不一致则服务不可用，不静默继续。
2. 640/1280 固定输入 shape 校验。
3. 33 张盲测全部产生一个几何合法框。
4. 40 张人工窗口回归全部产生一个几何合法框。
5. 两档同时命中时去重为一个最终框。
6. 高置信但宽、高或右边距非法的候选被拒绝。
7. 两档都无合法候选时返回 unknown，动作状态机为 noop。
8. 槽位框不越界，且不会因模型框宽高波动而缩放槽位间距。
9. 小窗口样例 `785x617`、`796x624` 和 `1275x1050` 能选择 640 档；标准大窗口可选择 1280 档。
10. 运行日志能还原 profile、候选、门控和最终决策。

建议把这些用例接入现有 VisionHarness；涉及动作许可的 unknown/noop 用例同时进入 CombatHarness。

## 9. 完成定义

只有同时满足以下条件才可把状态改为“已接入”：

- 两份 ONNX 已进入受版本控制或发布流程管理的运行时模型目录。
- 真实 ONNX Runtime 推理，不是固定框、假数据或测试桩。
- 双档融合、几何门控和固定槽位重建均已实现。
- 第 8 节自动化测试全部通过。
- 模型缺失、异常、无合法候选和 L2 不确定时均安全降级为 unknown/noop。
- Release 构建和实际启动验证通过。

在此之前，状态只能写作“模型已训练、等待后端接入”。
