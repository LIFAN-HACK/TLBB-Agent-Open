## 1. 本轮结论

1. 顶部中央青色系统反馈文字需要独立 L1 定位。`system_feedback_region_l1_v2` 已训练完成并通过 PT/ONNX 双格式测试，可以进入后端接入阶段。
2. 材料加工现有代码具备配方遍历和基础反馈状态机，但当前仍对全屏做 Toast OCR，且缺少“技能 -> 生活技能”可靠入口；不能宣称完整闭环可用。
3. 技能释放必须同时依赖槽位坐标、游戏内图标身份、CD 状态、技能策略和当前帧。控制技能是否允许释放由资产库策略决定，不能只按槽位盲放。
4. 物品资产已生成运行时保护索引，当前 20 个条目全部为 `Keep`，未知物品也默认保护；实际出售仍必须保持关闭。
5. 洛阳、苏州、大理、楼兰的驿站 NPC 只有官网参考候选，12 条有向路线均缺当前客户端的对话选项和到达证据；本轮只落只读路线骨架，不授权自动点击。

## 2. 不得改变的总体架构

```text
完整客户区帧
  -> L1 定位（窗口/HUD/反馈文字/槽位）
  -> 按 L1 源像素框裁剪
  -> L2 识别（OpenText/图标模板/图色/CD）
  -> 同一 frame_sequence 的时序融合
  -> 业务策略和状态机
  -> 输入门禁
  -> 键盘或鼠标动作
  -> 视觉回读确认
```

强制规则：

- 所有点击坐标必须来自当前帧 L1/L2 的源客户区像素框，不允许保存某个分辨率的绝对桌面坐标。
- L1 未命中、L2 为 `unknown`、帧过期、窗口失焦、角色会话变化或状态机不一致时一律 `noop`。
- 不新建与现有 `PerceptionHub`、`IOpenTextRecognizer`、`SkillCooldownRecognitionService`、`BagCleanupService` 平行的第二套链路。
- 已接入但动作未授权的模块继续只读；未接入模块不在 UI 中宣称可用。
- 每个动作都要有后置视觉证据。只有“点击成功日志”不能作为业务完成证据。

### 4.3 必须实现的运行链

1. 把 ONNX 和清单复制到 `src/TlbbAgent.Core/models/vision/system_feedback_region_l1_v2/`，由 `ModelArtifactRegistry` 校验 SHA256。
2. 复用 `YoloV8OnnxDetector`，新增单一职责的 `SystemFeedbackRegionDetectService`；结果写入当前 `PerceptionSnapshot`，不要另建全局缓存。
3. 坐标还原后执行强制后处理：
   - `abs(center_x - W/2) <= 0.11W`
   - `0.015 <= center_y/H <= 0.27`
   - 同水平带横向间距 `<= 0.08W` 时合并
   - 纵向间距 `<= 0.025H` 且横向中心差 `<= 0.12W` 时合并
4. 合并后的 crop 交给现有 `IOpenTextRecognizer`，槽位固定为 `OpenTextSlot.Toast`。
5. OCR 文本进入语义分类器，至少输出：
   - `MaterialExhausted`
   - `MaterialBusy`
   - `MaterialCompleted`
   - `Cooldown`
   - `InsufficientResource`
   - `InvalidAction`
   - `Unknown`
6. 每个结果携带 `frame_sequence`、源像素框、L1 置信度、OCR 置信度、规范化文本和时间戳。
7. `Unknown`、空 OCR、过期帧或同一帧之外的拼接结果不得触发动作。

禁止把 NPC 对话正文、聊天框、系统日志或面板文字回退为全屏 Toast OCR。这会把聊天内容误判成加工/冷却状态。

## 5. 材料加工真实状态机

### 5.1 入口策略

按顺序执行：

1. 当前帧检测到 `material_panel`：直接进入配方读取。
2. 未检测到面板，但右侧技能栏检测到已确认的材料加工图标：点击当前帧图标中心，随后等待面板出现。
3. 两者都没有：进入 `EntryUnavailable`。只有在“技能窗口、生活技能页签、材料加工条目”三个控件都完成 L1/L2 标注、不同位置回放和动作授权后，才允许执行“技能 -> 生活技能 -> 材料加工”的 fallback。
4. 当前代码没有第 3 步的可靠控件资产，因此本轮不得用固定坐标补齐。

### 5.2 配方处理流程

```text
Idle
 -> EnsurePanel
 -> ReadVisibleRecipes
 -> SelectRecipe
 -> ConfigureBatch
 -> StartCraft
 -> ObserveFeedback
 -> Busy | Completed | Exhausted | Blocked | Unknown
 -> NextRecipe | Stop
```

实现要求：

- 配方列表只从 `material_panel` 内裁剪，使用现有 `OpenTextMaterialRecipeListReader`，按规范化配方名去重。
- 处理当前可见配方后滚动列表；滚动前后配方集合连续两次相同即认为到底，避免无限滚动。
- 数量输入优先使用面板现有数量控件；无法可靠定位时保留默认值，禁止盲点数字框。
- 发起加工后立即进入 `BusyWait`，在 `MaterialBusy` 或底部进度条存在期间禁止重复点击制造。
- `MaterialCompleted` 只增加完成计数，不代表材料仍充足；回到同一配方继续尝试。
- 第一次 `MaterialExhausted` 只记候选；必须在不同 `frame_sequence` 上再次得到 Exhausted，且中间没有 Completed，才停止当前配方并切换下一配方。
- `Cooldown`、`InvalidAction`、`InsufficientResource` 分别记录原因；不能统一伪装成材料不足。
- 连续 5 次 `Unknown`、单配方 120 秒无状态变化、窗口消失或角色会话变化时安全停止。
- 全部配方结束后输出：配方名、成功次数、停止原因、最后反馈原文、帧号和耗时。

### 5.3 验收用例

- 面板已打开，至少两种配方依次加工。
- 加工中连续多帧不会重复点击。
- “你做了一个...”后继续同一配方。
- 两个独立帧均为“缺少材料”后切到下一配方。
- “你不能这样做”“冷却时间未到”“活力不足”分别进入不同状态。
- 左侧聊天出现“缺少材料”但顶部反馈区没有该文字时，不得停止加工。
- 面板不存在且入口不明时返回 `EntryUnavailable/noop`。

## 6. 技能身份、CD 和真实释放

### 6.1 决策条件

仅当以下条件全部成立才允许释放：

1. 当前帧 L1 已给出技能槽源像素框。
2. L2 图标匹配为 `Matched`，来源为 `icons_ingame`，不是官网候选图。
3. `ExpectedVisualSkillId` 与当前槽位身份一致。
4. 技能资产策略为 `hang_usable=true`。
5. CD 状态为 `Ready`；`Cooling/Unknown` 均不执行。
6. 目标、距离、玩家蓝量、宠物/骑乘/疲劳等业务前置条件满足。
7. 帧仍为当前窗口会话的最新帧。

### 6.2 为什么仍需要技能图标库

按槽位只能回答“按哪个键”，不能回答“这个技能是否允许自动释放”。控制技能、位移技能、下马技能、召唤技能和资源技能必须由 `SkillId -> policy` 决定。不同玩家调整技能摆放后，系统应重新扫描槽位并动态匹配资产库，而不是要求人工校准固定位置。

建议技能策略字段：

```text
skill_id, profession, action_kind, target_kind,
hang_policy(allow|conditional|deny),
requires_target, requires_pet, breaks_control,
min_mana_percent, cooldown_group, priority,
source(icons_ingame|official_candidate), runtime_authorized
```

### 6.3 CD 处理

- 当前运行链读取 `Ready/Cooling/Unknown`，不需要先获得精确剩余秒数才能安全释放。
- 灰罩和数字覆盖优先回答 `Cooling`；模板匹配只回答图标身份。
- 数字 OCR 可作为日志和调度优化，不能在视觉仍为 Cooling 时强制覆盖为 Ready。
- 按键后必须观察到 `Ready -> Cooling`、资源变化或顶部反馈之一；无后置证据则按失败处理，不连续重按。
- 底栏使用绑定按键；右侧无快捷键槽位只允许点击当前帧槽位中心。

### 6.4 安全策略

- `control/interrupt/movement/dismount/summon` 默认 `conditional` 或 `deny`，不能加入普通伤害轮转。
- 未校准门派、官网图标候选、Top-1 低于阈值和高相似冲突一律 `unknown/noop`。
- 血祭/共生必须同时满足玩家阈值、宠物技能身份、宠物状态和 fatigue/mounted 门禁；任一 unknown 即不点。

## 9. 小地图和战斗轮询约束

- `resource_marker`、菱形或四边形采集点不是怪物证据。
- 怪物黄点存在时为 `Present`；边缘遮挡导致的单帧 absent 只能 `noop`。
- 继续使用 `ObservationSequence` 去重；至少 1200ms 窗口内 5 个独立 absent 帧、跨度不小于 800ms，并结合 3 次目标选择失败，才允许进入无怪分支。
- 地图闪烁圈是附加视觉特征，不作为怪物存在的唯一依据。
- 修改小地图逻辑后必须同时通过 `VisionHarness` 和 `CombatHarness`。

## 10. 全局状态优先级

从高到低：

1. 窗口失焦、角色会话变化、截图失败：全部动作停止。
2. 死亡/复活窗口、通用确认框：暂停其他控制器；未识别时不点击。
3. 材料加工 Busy、传送中、读条中：禁止战斗和重复交互。
4. 商店/背包/月卡/银行窗口：只允许所属控制器处理，其他控制器 `noop`。
5. 战斗：目标 HP、Dead/Gone、小地图和技能策略按当前已验证链路运行。

同一时刻只能有一个控制器持有输入租约。租约必须绑定 `window_id + role_session + frame_sequence`，超时或窗口变化自动释放。
